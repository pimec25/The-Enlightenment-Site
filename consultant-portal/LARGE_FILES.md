# Large Excel workbooks

The upload form uses a separate background flow for all `.xlsx` workbooks, up to 100 MiB (104,857,600 bytes). Word and PowerPoint retain a 30 MiB limit. No new packages, public buckets, privileged credentials or billing changes are required.

The browser sends 4 MiB pieces sequentially, retries interrupted pieces, and displays progress. The server verifies Consultant identity and CSRF for mutations, derives ownership from the verified session, uses random IDs, checks declared and received sizes, rejects out-of-order or conflicting pieces, and keeps temporary originals on disk. A single worker processes workbooks while status requests remain responsive. Up to four unsaved uploads may coexist. Expired inactive temporary files are removed on the next start; a service restart loses unsaved work.

Office archives are checked incrementally, including declaration checks spanning buffer boundaries, 1.5 GiB maximum expanded size, entry count, compression ratio, encryption and macro checks. Pinned openpyxl 3.1.5 loads metadata; pinned lxml 6.1.3 reads one worksheet row at a time with external entities/network disabled. Only analysis columns are decoded and retained. Customer/product/QUAD calculations use all eligible rows together. Current and prior periods remain governed by the selected cutoff and Request Date. Very large unique-group counts can still exceed available processing resources; file size alone is not a guarantee for every possible workbook.

After processing, the results page offers Save records. Saving runs in the background: each original piece is stored as a JSON object under the existing private `consultant-analysis-records/<owner>/parts/` prefix with its SHA-256 and size. The normal saved-record manifest is published last. Each storage object stays below existing per-object limits. Duplicate retries verify equality. Downloads validate and stream pieces in order. Old inline-original records remain supported. Ownership RLS remains unchanged. Storage quota and network speed still apply. An interrupted save may leave unlisted private pieces; retries reuse them. No deletion policies were added.

Completed uploads/drafts expire after one hour. Saving releases their temporary source/report memory. Sessions may require reopening from the Consultant dashboard after one hour or a deployment. Raw record JSON is limited to 45 MiB; very large calculated reports receive an explicit save failure rather than false success.

Verification includes 100 MiB declared-size acceptance and oversize rejection, authentication and ownership, CSRF, missing pieces, duplicate/conflicting retries, archive checks, background processing, save retry, multiple-piece reconstruction and original hashes. The full user workbook was analyzed locally with the selected cutoff 2026-10-03: 42,256 current rows, 49,064 prior-comparable rows, 1,978 current loss rows; report approximately 7.8 MiB.

The projected reader produced an identical full report to the standard reader for the 95.8 MiB, 108,612-row, 268-column source workbook, in 39.91 seconds locally. Standard-reader peak memory including JSON serialization was 138.75 MiB. Tests also compare sparse rows and both Excel date epochs. Report calculation logic is shared between readers.
